## The coordinator's loop

One parcel at a time, in the order of the table. Never two helpers at once.

1. Once, at the start: `git checkout main && git pull --rebase`, then `git checkout -b review/2026-11-14-findings`. Run `node --test 2>&1 | grep -E "^# (pass|fail)"`: it must say `# fail 0`. Write down the `# pass` number. If it fails, stop and call the user.
2. Take the first parcel not marked `[x]`. If it says **coordinator**, do it yourself. Otherwise call one helper (the Agent tool, `subagent_type: "general-purpose"`, `model`: the model of the parcel, `run_in_background: false`) with the text of "What to tell every helper" followed by the whole text of the parcel.
3. When the helper comes back, check, in this order:
   - `git status --short` shows only `docs/review-2026-11-14.md`.
   - `node --test 2>&1 | grep -E "^# (pass|fail)"` says `# fail 0` and the same `# pass` number as in step 1 (a review changes no test).
   - In this file, the section of the parcel no longer says `(pending)`, and every finding in it has the five fields of "The shape of a finding".
4. If a check fails: `git checkout -- . && git clean -fd` is **not** allowed; instead `git stash -u` (nothing is lost), then call a helper one model up (haiku, sonnet, opus, fable) with the same text plus what failed. If that also fails: stash again, stop and call the user.
5. If all checks pass: mark the parcel `[x]` in this file, `git add docs/review-2026-11-14.md`, commit with the message `Review desk: review of 2026-11-14, <the parcel's title>` ending with the attribution lines your session was given, and `git push -u origin review/2026-11-14-findings`. **Do not open the pull request yet** (a pull request, once opened, gets no more commits: `docs/desks.md`).
6. Tell the user in one or two lines, in Brazilian Portuguese, and go to the next parcel.

**Stop and call the user when:** the tests fail before a parcel; a parcel failed twice; a helper changed any file other than this one; a helper says the text of its parcel does not match the code; a push is refused twice.

## The shape of a finding

```
### <parcel>.<n> <one line that says the defect> — <high | medium | low> — <read | measured | opinion>
**Where:** file and function (and the commit, when it helps).
**What happens:** two to five sentences. For a measurement: the scene, the numbers, how to repeat it.
**Recommendation:** what to do, and for whom: Rules desk, Screen desk, or a question for the user (one line, with the readings he can choose from).
```

Severity: **high** = the game does something the user did not decide, or a guarantee written in the docs is false; **medium** = fragile, will break with the next content; **low** = docs, names, comments.
