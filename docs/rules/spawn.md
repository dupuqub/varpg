# Spawn

## Spawn

- Every X time, Y spawn. For each map, exactly what appears and when is known in advance.
- **The spawn events (the user, 2026-11-15, issue 61; built, data version 62).** Every map (`DEFINITIONS.maps`) has `spawns`, an **array of hand-written objects**, each a spawn event `{ initialFrame, count, type }`: one type per object, no repetition field. Decided by the user, do not reopen: events with the same `initialFrame` resolve together, **in index order**, and the array may be written in any order; **spawn is the last thing of a step**, so what is born in the step of frame N exists from frame N + 1 (`initialFrame` 0 too: the state at frame 0 has no Biters); each actor is born off the screen and inside the window through `birthOffset`, with no search for a free place, with the draws and the id of its pair (event index, nth; see "Draws and ids" under "Actor" (docs/rules/actor.md)); new actors go to the **end of `state.actors`**, never reordered; the births are decided by `state.frame` alone, with no state of the spawn (no counter, no list of who was born), so going back in time and playing gives the same births and nobody is born twice; **every birth writes a journal line**; and an **unknown `type`** is skipped with an error line in the journal while the other events still spawn (see the rule below). The rule is `spawnEvents` (stage 7b of `step`, see `docs/step-order.md`) and `spawnActor`. Chamber 2's array (`maps.chamber2`) is the PLAN desk's guess, to be tuned by playing: a crowd of Biters at frame 0 and smaller waves at regular frames after it (the numbers and their reasons are in `src/data.js`; the worked numbers in test 238). Chamber 1's array (`maps.chamber1`) has one event: 1000 Dummies at frame 0 (the user, issue 62; see "The Dummy" (docs/rules/actor.md); test 245). Tests 238 to 247.
- **The agent's readings of the spawn (not the user's words; for him to confirm when it comes up):** (1) the spawn runs after the shield (stage 7) and before the frame counter goes up, so it compares `initialFrame` with `state.frame` of the step and its lines carry `state.frame + 1`, the frame the newborn is first seen in, as `recordHit` does; stage 8 (the mission ends) stays after the counter. (2) After the avatar's death nothing is born: stage 7b is skipped when `worldStops` says so, and an aborted state does not step at all (test 243). (3) A newborn is complete at the end of the step that made it: `finalizeStatic`, `finalizeDynamic` and its cells, so `actor.cells` is right at the end of every step (tests 100 and 110). (4) The rules never read the journal; a run with no journal gives the same state (tests 160 and 238). (5) The array lives in the entry `DEFINITIONS.maps` (a map is not terrain: the ground comes from the seed, the spawns are a schedule), and **the state names its map in `state.map`** (`"chamber1"`, `"chamber2"`), set when the state is made, because `step` must know which array to read and receives no map; it is the identity of the schedule, like the seed, and not a state of the spawn. (6) The numbers of an event (`initialFrame`, `count`) must be whole and 0 or more, refused when the data loads, as what poisons the arithmetic always was; the type is not checked at load (the user's rule below) (test 242). (7) The birth line is `{ frame, event: "birth", spawn, id, type, position }` (the issue named its content) and the error line `{ frame, event: "error", error: "unknown type", map, spawn, type }` (the map and the index say where). (8) The avatar is not made from ranges, so it is in no map; the Dummy is born from its map's array like every actor (the user, issue 62), and what it rolls for itself (its first angle) goes through `OWN_ROLLS` (test 246).
- **Who an actor attacks (the user, 2026-11-16, issue 71).** An actor attacks what the target of its attack names in the data (`target: { pick, tag }` in `src/data.js`); an actor with no attack chases nobody. Two examples: the **Biter**, whose bite aims at the closest "ally" (`target: { pick: "closest", tag: "ally" }`, the avatar is the only one today), so it chases and bites (`think`); and the **Dummy**, which has no attack, so it only wanders and turns at a contact (`OWN_ROLLS`, `turnDummy`). The first sentence of this rule is kept in `docs/decisions.md`.
- An actor that leaves the window reappears on the opposite side. So there is a limited number of actors always present, almost all on screen. **Implemented for every actor except the avatar** (`wrapIntoWindow`; see "The Dummy" (docs/rules/actor.md) below).
